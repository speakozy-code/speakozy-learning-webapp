# Speakozy - تطبيق التعلّم (مشروع مستقل)

تطبيق ويب لتعلّم الإنجليزية، مستقل تمامًا عن نظام العمليات القديم. لا توجد أي كتابة على بيانات الإنتاج إلا بعد تهيئة البيئة ومراجعة صريحة.

## المنهج المستورد من درايف (E1 → Upper 2)
- `src/lib/driveCurriculum.ts`: 11 مستويات مرتّبة (E1, E2, E3, Pre 1, Pre 2, Pre 3, Inter 1, Inter 2, Inter 3, Upper 1, Upper 2) و73 جلسة من ملفات العروض التقديمية على Google Drive، بالترتيب من المستوى الأول لآخره.
- كل جلسة فيها نص الدرس كامل، تمارين، أسئلة اختبار، شرائح قواعد، وقائمة كلمات.
- كل كلمة ليها معنى عربي، تعريف إنجليزي، نوع الكلمة، نطق صوتي مكتوب، وملف صوت أصلي من القاموس العالمي.
- زراير النطق في بطاقة الكلمة بتفتح YouGlish بأربع لهجات: أمريكي، بريطاني، أسترالي، وكندي.
- مصادر الإثراء: `api.dictionaryapi.dev` للتعريف والنطق، وWiktionary كبديل، وGoogle Translate للمعنى العربي. مفيش تعريفات متخترعة.
- البيانات بتتولّد من سكربت محلي، والاختبارات بتفحص سلامة المنهج في `scripts/test-curriculum.mjs`.

## المحتوى والقاموس
- المنهج مولّد في `src/lib/curriculum.ts`: 15 مستوى × 7 جلسات = 105 جلسة، 315 سؤال، و525 كلمة.
- كل جلسة فيها 5 أقسام: مفردات، قاعدة Grammar، موضوع/مهارة، أمثلة وتمارين، ملخص.
- القاموس عالمي وليس قائمة محلية: يبحث في الكلمات المحفوظة، ويسأل مصدرًا عالميًا مفتوحًا تلقائيًا عن أي كلمة تكتبها، ويحفظ النتيجة محليًا لتبقى قابلة للبحث. المصدر قابل للتبديل في `VITE_DICTIONARY_API`.
- الكلمات اللي يضيفها المستخدم أو المستوردة من العرض تُحفظ في مجموعة `dictionary` المشتركة على الخادم، فتظهر لكل الطلاب في وضع Firebase.
- النتيجة خارجية بتتخزن مؤقتًا محليًا، ومفيش أي مفتاح API مطلوب. لو الشبكة مش متاحة، المستخدم يقدر يضيف الكلمة يدويًا.
- مراجعة سريعة للكلمات المحفوظة على شكل بطاقات، ونطق بالصوت عبر المتصفح أو ملف صوتي متاح.

## التشغيل
```bash
npm install
npm run dev        # http://localhost:3000
npm test           # اختبارات منطق المجال
npm run build      # فحص أنواع + بناء الإنتاج في dist/
```

## الوضع التجريبي
إذا تركت ملف `.env` فارغًا، يعمل التطبيق في وضع تجريبي محلي:
- البيانات وهمية بالكامل ومحفوظة في `localStorage` على جهازك فقط.
- حسابات جاهزة: `mariem@speakozy.demo` / `demo123` (طالب)، و `admin@speakozy.demo` / `admin123` (مدير).
- لا يوجد أي اتصال بقاعدة بيانات أو إرسال إشعارات حقيقية.

## الربط بـ Firebase
انسخ `.env.example` إلى `.env` واملأ بيانات مشروع Firebase. بعدها:
1. فعّل Email/Password في Firebase Authentication.
2. طبّق `firestore.rules` (القواعد تتحقق من دور المستخدم على الخادم، وليس من الواجهة).
3. أنشئ مستندات `users/<uid>` بالحقول: `name, email, role, active, levelId, maxLevelId, createdAt`.
4. انشر `dist/` على Firebase Hosting. لا تنشر على الموقع الحي قبل مراجعة المعاينة.

## الرفع / النشر (جاهز ومش منفّذ)
الملفات جاهزة، ومفيش أي رفع حصل لحد دلوقتي:
1. انسخ `.env.example` إلى `.env` واملأ قيم Supabase (أو Firebase) **قبل** البناء النهائي. من غير `.env` البناء هيطلع بالوضع التجريبي.
2. شغّل `bash scripts/deploy-check.sh` — بيعمل الاختبارات، البناء، ويتأكد إن `dist/` و`firebase.json` و`supabase/schema.sql` موجودين.
3. `firebase.json` مضبوط على موقع منفصل اسمه `speakozy-learning` فيه SPA rewrite. **ما تنشرش على `speakozy-94075` ولا على `speakozy.web.app`** لأن ده نظام العمليات الحي.
4. بعد ما تختار المشروع: `firebase use --add <project>` وبعدين `firebase deploy --only hosting:speakozy-learning`.
5. شغّل `supabase/schema.sql` في SQL Editor قبل استخدام الوضع المتصل.

## البنية
- `src/types.ts` — مخطط البيانات (كيانات منفصلة ومترابطة).
- `src/lib/domain.ts` — منطق خالص: التصحيح، حالة الجلسة، النقاط، الخصوصية.
- `src/lib/store.tsx` — طبقة بيانات واحدة تبدّل بين الوضع التجريبي وFirebase.
- `src/pages/Student.tsx` — مساحة الطالب.
- `src/pages/Admin.tsx` — لوحة الإدارة.
- `firestore.rules` — صلاحيات الخادم.

## سياسات مهمة
- حل الاختبار لا يعني النجاح؛ الإجابات الكتابية والنهائية تنتظر اعتماد الإدارة.
- كل نقطة لها `refId` يمنع احتسابها مرتين.
- لوحة الأبطال تعرض الاسم المختصر والنقاط فقط، مع إمكانية إخفاء طالب.
- الدرجات والشهادات لا تُنشأ إلا بعد اعتماد إداري.
- لا توجد مفاتيح أو كلمات مرور في الكود أو الحزم؛ المفاتيح تقرأ من متغيرات البيئة.
